# Рабочее место администратора Balance

Административный маршрут: `/admin`. Доступ определяется сервером и RLS базы,
а не только скрытием кнопок.

Главный экран объясняет задачу администратора и показывает реальные задачи:
неполные опубликованные карточки, черновики, незакрытые обращения и ошибки Лео.
При недоступных данных показывается отсутствие загрузки, а не нулевой счётчик.
Основные направления: «Что требует внимания», «Содержимое», «Проверка плана»,
«Обращения». В содержимом доступны упражнения, материалы и проверка полноты.
Редкие настройки, версии, учётные записи и журнал находятся в «Дополнительно».
Каждая роль видит только свои задачи и доступные направления. Порядок подготовки
упражнения объясняется на главном экране: черновик → проверка → публикация.

## Роли

- Владелец: все разделы, блокировка других учётных записей, назначение
  административного уровня другим существующим администраторам.
- Редактор: упражнения, материалы, вопросы, правила, карта, настройки плана,
  качество каталога, симулятор и версии. Нет доступа к другим профилям и обращениям.
- Поддержка: обращения и диагностика. Нет редактирования каталога и чтения версий.

Существующий администратор без строки `admin_access` сохраняет уровень владельца.
Обычного пользователя нельзя повысить через этот интерфейс: начальное назначение
`profiles.role=admin` выполняет доверенный оператор. Изменение собственного уровня
и блокировка собственного аккаунта через интерфейс запрещены.

## Содержание и планы

Новые упражнения и статьи создаются как черновики. Для публикации сервер требует
название, инструкцию/текст и HTTPS-источник; для упражнения также целевые области
и доступное место. Наличие источника не подтверждает клиническую проверку.
Ключ, тип и существующие значения вариантов опубликованного вопроса закреплены,
чтобы старые ответы оставались совместимыми; подписи и новые варианты редактируются.

Симулятор использует настоящий `make_plan`, вымышленные ответы и выбранную дату.
Он не загружает опросы, дневники или историю выполнения других пользователей.
Варианты, не выбранные в дневной объём, отделяются от неподходящих упражнений.
Симуляция не моделирует отзыв после упражнения или новую запись дневника.
Проверка покрытия показывает опубликованные лёгкие упражнения по областям,
включая варианты сидя. Проверка ограничена 500 загруженными записями каталога.

## Версии и журнал

Триггеры сохраняют снимки до/после и автора в одной транзакции с изменением
содержимого. Журнал действий для этих операций также записывается атомарно.
История начинается с установки миграций, а не восстанавливается задним числом.
Восстановление существующей записи создаёт новую версию; проверяется номер её
текущей редакции. При параллельном изменении восстановление отклоняется.
Удалённые записи не восстанавливаются через интерфейс. Восстановление вопроса
не может менять ключ/тип или удалять существующие варианты ответа.

## Поддержка и система

Пользователь отправляет обращение из профиля и там же читает ответ. Автоматически
дневник, ответы опроса и видео не прикладываются. Пользователь видит только свои
обращения и не может менять статус или ответ поддержки.
Администратор переводит обращение в работу, отвечает и закрывает его.

Диагностика проверяет чтение базы и наличие конфигурации внешнего ИИ.
Ключи не отображаются. Наличие ключа не подтверждает доступность провайдера.
Журнал запросов Лео хранит статус, модель, время ответа и токены из ответа провайдера.
Тексты вопросов, ответы и данные плана в технический журнал не записываются.
Диагностика показывает до 1000 последних событий за 30 дней и 20 последних
запросов. Денежная стоимость не оценивается; это не замена отчёту провайдера.
[Формат usage в Responses API](https://developers.openai.com/api/reference/resources/responses/methods/create).
При отсутствии ключа Лео использует существующие готовые подсказки.

## Проверка

- `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`.
- `tests/admin.browser.mjs`: изолированные браузерные fixtures, без реальных
  изменений аккаунтов и каталога.
- В реальной базе проверены триггер версий, восстановление, конфликт редакций,
  RLS обычного пользователя, права редактора/поддержки и ответ на обращение.
  Проверочные изменения выполнялись в транзакциях с `ROLLBACK`.
- Supabase security advisor после изменений: новых замечаний по RLS/функциям нет.
  Существующее предупреждение проекта: отключена защита от скомпрометированных
  паролей. Настройка не изменялась.
  [Документация Supabase](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection).

Исходник миграций: `database/admin_workspace.sql`. Миграции уже применены к базе
проекта приложения через Supabase MCP; не запускайте файл повторно без проверки
истории миграций.
